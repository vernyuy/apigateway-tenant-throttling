# Company Directory API: tenant isolation on Amazon API Gateway

A deployable sample of a **multi-company employee directory** that demonstrates tenant isolation at the API edge:

- **Performance isolation.** Every company (tenant) has its own API key in a usage plan for its tier, so one busy company cannot throttle the others.
- **Data isolation.** Employees authenticate with Amazon Cognito, the token names their company, and the API only ever reads that company's directory.

It is built with AWS CDK (TypeScript) and includes a React platform console: an overview dashboard, company management with a per-company detail panel, and a **traffic lab** for watching one company being throttled while another is unaffected.

## What the sample demonstrates

| Concept | Implementation |
|---|---|
| One API key per company, generated by API Gateway; only the key ID is stored | [`lambda/lib/api-keys.ts`](infra/lambda/lib/api-keys.ts) |
| One usage plan per tier, with limits applied to each key independently | [`lib/tiers.ts`](infra/lib/tiers.ts), [`lib/tenant-api-stack.ts`](infra/lib/tenant-api-stack.ts) |
| A stage-level throttle as the ceiling for all companies combined | [`lib/tiers.ts`](infra/lib/tiers.ts) |
| Cognito authentication with an immutable `custom:tenant_id` claim | [`lib/tenant-api-stack.ts`](infra/lib/tenant-api-stack.ts), [`lambda/lib/users.ts`](infra/lambda/lib/users.ts) |
| Built-in Cognito authorizer, so no Lambda runs in front of the throttle | [`lib/tenant-api-stack.ts`](infra/lib/tenant-api-stack.ts) |
| Binding the API key to the caller's company | [`lambda/employees.ts`](infra/lambda/employees.ts) |
| Directory reads scoped to the company in the token | [`lambda/lib/employees.ts`](infra/lambda/lib/employees.ts) |
| Tier changes by moving a key between plans | `syncTier` in [`lambda/lib/api-keys.ts`](infra/lambda/lib/api-keys.ts) |
| Key rotation, suspension and per-company usage | [`lambda/admin.ts`](infra/lambda/admin.ts) |
| Access logs recording the API key and user of every request | [`lib/tenant-api-stack.ts`](infra/lib/tenant-api-stack.ts) |

## Tiers

| Tier | Usage plan | Limit per company | Daily quota |
|---|---|---|---|
| Basic | `<stack>-basic` | 2 requests/s, burst 4 | 5,000 |
| Premium | `<stack>-premium` | 10 requests/s, burst 20 | 50,000 |
| Enterprise | `<stack>-enterprise` | 50 requests/s, burst 100 | 500,000 |

Usage plans are named after the stack (for example `CompanyDirectoryApi-basic`), because the admin function looks them up by name.

The limits are intentionally low so that throttling is visible from a browser. Change them in [`lib/tiers.ts`](infra/lib/tiers.ts).

## Getting started

**Prerequisites:** Node.js 20 or later, credentials for a sandbox AWS account, and a [bootstrapped](https://docs.aws.amazon.com/cdk/v2/guide/bootstrapping.html) CDK environment.

```bash
npm install
npm test           # CDK assertion tests, no AWS calls
npm run deploy     # deploys the stack and writes web/.env.local (see web/.env.example)
npm run web        # starts the console on http://localhost:5173
```

Retrieve the admin token with the command in the `AdminTokenCommand` stack output:

```bash
aws secretsmanager get-secret-value --secret-id <AdminToken ARN> --query SecretString --output text
```

> **Note:** `cloudWatchRole: true` sets the API Gateway CloudWatch Logs role for the whole account and Region, which access logging requires. Check for an existing configuration before deploying.

## Walkthrough

1. Paste the admin token and select **Connect**.
2. On **Companies**, select **New company** and create **Acme Robotics** on Basic and **Initech Labs** on Premium. Each receives a Cognito user, an API key and a sample directory. The credentials are displayed once.
3. Wait about a minute for the new API keys to become active; until then, API Gateway rejects them with a 403. Meanwhile, select a company to open its detail panel, then the **Directory** tab. Each company sees only its own employees.
4. In the **Traffic lab**, set both companies to 5 requests per second and select **Run for 20s**.
   - Acme Robotics is fully successful for the first second or two (the burst), then settles at roughly 2 successful requests per second; the remainder are throttled (429).
   - Initech Labs is unaffected.
   - Use **Every company at** to set every company to ½×, 1×, 2× or 5× its own limit, and **Duration** to change the run length.
5. Set Acme Robotics to 10 requests per second and run again. It still gets about 2 successful requests per second; only the throttled count grows.
6. In Acme Robotics' detail panel, change the tier to Premium, wait a few minutes for the change to take effect, and run again. The API key does not change.
7. Select **Suspend key** for Initech Labs and run again. API Gateway rejects every request with a 403.
8. Open the **Usage** tab to view a company's daily request count from `GetUsage`. The **Overview** page totals today's requests across all companies.

Screenshots of each step, with measured results, are in the [article](docs/blog-post.md#31-a-worked-example).

> **Lambda concurrency.** Every successful request runs a Lambda function, and new AWS accounts can be limited to as few as 10 concurrent executions. The traffic lab shows an estimate of what your account can serve and warns when the combined rate is above it; beyond that point, requests fail with 5xx errors rather than 429s. Check your limit with `aws lambda get-account-settings` and request an increase through Service Quotas if needed.

The API can also be called from a terminal. The script signs in to Cognito and then sends the ID token with the company's API key:

```bash
API_URL=... REGION=... CLIENT_ID=... USERNAME=... PASSWORD=... API_KEY=... node infra/scripts/call-api.mjs
```

## Cleaning up

API keys and Cognito users are created at runtime, so `cdk destroy` does not remove them. Delete the companies in the console first, then run:

```bash
npm run destroy --workspace=infra
```

## Cost

All services are serverless and billed per use. Ongoing charges are one Secrets Manager secret (the admin token) and CloudWatch Logs storage. The Cognito user pool uses the Lite feature plan, which includes a free tier for monthly active users. API keys and usage plans carry no separate charge. Delete the stack when finished.

```
web/                            React (Vite) platform console: overview, companies, traffic lab, settings

```

## Simplifications for demonstration purposes

These shortcuts keep the sample small. Do not carry them into production.

- The browser holds each company's username, password and API key so the traffic lab can act on its behalf. In production, users set their own passwords and API keys stay out of the browser.
- Sign-in uses `USER_PASSWORD_AUTH`. Prefer SRP or the Cognito managed login pages.
- CORS allows any origin. Restrict it to your application's domain.
- The admin routes use a single bearer token. Use Cognito groups, IAM or your identity provider for administrators.
- Listing companies uses a DynamoDB `Scan`. Use a query with pagination at scale.
